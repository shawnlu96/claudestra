# 中继（relay）：一个地址，配对即到自己的机器

bridge 只向外连一条 WebSocket 到中继。之后手机、别的电脑的浏览器打开 **`https://<中继域名>/`** 就是 Claudestra 的网页——网页由中继托管，所有用户拿到同一份；第一次扫码 / 输码把「这个浏览器」配对到你的 Mac，以后打开直接进；一个浏览器可以配对多台机器，页内切换。别人的 Claudestra 也能经中继调你开放的 agent。你的机器不需要公网 IP、不开端口、不装 Tailscale。协议与边界见 [protocol.md](./protocol.md)，自己跑一个中继见 [self-host.md](./self-host.md)，整体设计见 [../design-hosted-frontend.md](../design-hosted-frontend.md)。

## 在你的电脑上启用

`bun run setup` 的「手机访问」一步默认就配中继：回车用官方中继 `wss://relay.sunstriker.cc`，装完直接打出配对二维码。手动配等价于 `.env` 加一行，重启 bridge：

```
RELAY_URL=wss://relay.example.com      # 中继地址（官方托管或自建）
RELAY_NAME=mini                        # 可选：这台机器在中继目录里的名字（也是旧版子域名的标签）；不配就按主机名生成
```

bridge 日志会打出 `🛰 中继: 已连接 …`。机器在中继上的身份是实例密钥的指纹（`claudestra relay-status` 里能看到），网页地址与它无关——大家都打开同一个 `https://<中继域名>/`。

## 从手机 / 别的浏览器进来：配对

电脑上运行：

```
claudestra pair            # 默认签给自己：全部 agent + master + 远程终端 + 管理
claudestra pair --guest 小王 --agents a,b   # 给别人一个只看得到 a、b 的访客身份
```

终端打印一个二维码、一条链接（`https://<中继域名>/pair#<指纹>.<秘密>`）和一个 8 位短码（10 分钟有效、只能用一次）。三种方式任选：

- **扫码**：手机相机扫二维码，Safari 打开就是配对页，自动完成；
- **点链接**：把链接发给自己，在任何浏览器打开；
- **输短码**：在 `https://<中继域名>/` 首页（或 `/pair` 页）输入 8 位码——手机进入「等待确认」，**电脑终端里点头**（`claudestra pair` 会列出待确认项，网页的设备面板也能批准）之后才发凭据，所以短码被人猜到也没用。

配对成功后这个浏览器拿到一份**由你自己的 bridge 签发、bridge 自己校验**的设备凭据（HttpOnly cookie，只对这台机器的 `/m/<指纹>/` 路径有效）。中继不做账号、不做授权，只转发。清了浏览器数据就是丢了这台设备，再配一次即可；在网页「设备」面板或 `DELETE /api/v1/devices/:id` 可以随时撤销某台设备。`/login` 已经不存在，直接跳到 `/pair`。

没连中继的机器（Tailscale / 局域网直连 bridge）也一样配对：打开 `<入口地址>/pair` 输短码，或 `claudestra pair --url <入口地址>` 直接出二维码。

## 邀请别人的 Claudestra 一起协作

设置 → Peer 协作 → 邀请对方，勾选开放哪些 agent，会得到一条链接 `https://<中继域名>/i#…`。对方点开：

- 他的浏览器已经配对过自己的 Claudestra → 直接到他的「加入」页，点一下完成；
- 还没配对 → 先配对自己的机器再接续；
- 没有 Claudestra → 引导安装。

加入后两边通讯录互相出现、带在线状态；`send_to_agent("<agent>@<对方>")` 与 Peer 面板照旧。反向开放在同一条关系里点一下即可，不需要第二条链接。收回在 Peer 面板做，本机立即生效。

## 这版能保证什么、不能保证什么

- 中继**不能**冒充任何实例发请求（peer 请求带实例 Ed25519 签名，接收方验签；它看得到的 peer token 单独拿去也用不了——接收方要求签名钥匙就是那个 peer 的），也不能替陌生人敲你的门（只有你列为联系人的实例能给你发帧；兑换邀请是唯一例外，限流）。设备凭据由你的 bridge 签发和校验，中继拿不到签发权。
- 中继**看得到**隧道里的明文（它就是 HTTPS 的终点，包括设备 cookie）和 peer 请求的内容，托管的 JS 也跑在你的浏览器里——信任托管中继 = 信任运营方，和任何 SaaS 一样。端到端加密是下一版。不放心就自建，或者走 bridge 直托管 + 自带域名（JS、更新源、TLS 全在自己手里）。
- 同一主源上配对了多台机器时，一台机器的输出若突破清洗 / CSP，能在页面存活期间借用你在这个浏览器里其它机器的凭据（偷不走，但挡不住借用）——前端按设计 §8.7 收紧了 CSP 与 markdown 清洗。
- 中继不存代码、会话、提示词、凭据；目录库里只有实例公钥、指纹、名字、最近在线时间和配对短码。
- 大文件不过中继：帧 256 KiB 上限，超过的走两端直连（后续）。

## 网页里怎么做

顶栏切换已配对的机器；「设备」面板列出每台机器上已配对的浏览器（名字、授权范围、最近使用），可撤销；Peer 面板顶部有「配对新设备」——点一下网页里直接出二维码、链接和短码，不用开终端。

## 排障

- bridge 日志里看 `🛰 中继:` 开头的行；`N 秒后重连中继` 一直刷说明连不上。
- `claudestra relay-status`：连接状态、指纹、名字、最近一次错误、联系人在线情况。`claudestra doctor` 的「手机访问」组也有中继一行。
- 常见情况：
  - `RELAY_URL` 只写主机名即可（客户端会补 `/v1/ws`）；写了别的路径就按写的连，反代没挂在那个路径下就一直重连。
  - 电脑睡眠或断网：网页里这台机器显示离线，醒来自动重连，刷新即可。
  - 网页说「这台机器需要升级」：bridge 版本低于前端要求的 `minClient` / `apiVersion`，在那台机器上 `claudestra update`。
  - 旧的 `https://<名字>.<中继域名>` 子域名地址：只对还没升到路径模式的旧 bridge 保留，截止日之后回 410 并指向新入口；重新打开 `https://<中继域名>/` 配对一次即可。
  - 一分钟内配对码试太多次会被中继挡（429）；配对码本身 10 分钟过期、只能用一次，重新 `claudestra pair`。
