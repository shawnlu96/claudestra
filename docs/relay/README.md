# 中继（relay）：一个地址，配对即到自己的机器

bridge 只向外连一条 WebSocket 到中继。之后手机、别的电脑的浏览器打开 **`https://<中继域名>/`** 就是 Claudestra 的网页——网页由中继托管，所有用户拿到同一份；第一次扫码 / 输码把「这个浏览器」配对到你的 Mac，以后打开直接进；一个浏览器可以配对多台机器，页内切换。别人的 Claudestra 也能经中继调你开放的 agent。你的机器不需要公网 IP、不开端口、不装 Tailscale。协议与边界见 [protocol.md](./protocol.md)，自己跑一个中继见 [self-host.md](./self-host.md)，整体设计见 [../design-hosted-frontend.md](../design-hosted-frontend.md)。

## 在你的电脑上启用

`bun run setup` 的「手机访问」一步默认就配中继：回车用官方中继 `wss://relay.sunstriker.cc`，装完直接打出配对二维码。装好之后才想开的，网页「设置 · Peer 协作」的中继卡点「一键接入官方中继」即可：写进 `.env` 并当场连上，不用重启（只认带管理权限的设备凭据，`POST /api/v1/relay/setup`）。手动配等价于 `.env` 加一行，重启 bridge：

```
RELAY_URL=wss://relay.example.com      # 中继地址（官方托管或自建）
RELAY_NAME=mini                        # 可选：这台机器在中继目录里的名字（也是旧版子域名的标签）；不配就按主机名生成
```

bridge 日志会打出 `🛰 中继: 已连接 …`。机器在中继上的身份是实例密钥的指纹（`claudestra relay-status` 里能看到），网页地址与它无关——大家都打开同一个 `https://<中继域名>/`。

## 从手机 / 别的浏览器进来：配对

电脑上运行：

```
claudestra pair            # 默认签给自己：全部 agent + master + 远程终端 + 管理
claudestra pair --guest 小王 --agents a,b   # 给别人一个只看得到 a、b 的访客身份
```

终端打印一个二维码、一条链接（`https://<中继域名>/pair#<指纹>.<秘密>`）和一个 8 位短码（10 分钟有效、只能用一次）。三种方式任选：

- **扫码**：手机相机扫二维码，Safari 打开就是配对页，自动完成；
- **点链接**：把链接发给自己，在任何浏览器打开；
- **输短码**：在 `https://<中继域名>/` 首页（或 `/pair` 页）输入 8 位码——手机进入「等待确认」，**电脑终端里点头**（`claudestra pair` 会列出待确认项，网页的设备面板也能批准）之后才发凭据，所以短码被人猜到也没用。

配对成功后这个浏览器拿到一份**由你自己的 bridge 签发、bridge 自己校验**的设备凭据（HttpOnly cookie，只对这台机器的 `/m/<指纹>/` 路径有效）。中继不做账号、不做授权，只转发。清了浏览器数据就是丢了这台设备，再配一次即可；在网页「设备」面板或 `DELETE /api/v1/devices/:id` 可以随时撤销某台设备。`/login` 已经不存在，直接跳到 `/pair`。

没连中继的机器（Tailscale / 局域网直连 bridge）也一样配对：打开 `<入口地址>/pair` 输短码，或 `claudestra pair --url <入口地址>` 直接出二维码。

## 邀请别人的 Claudestra 一起协作

设置 → Peer 协作 → 邀请对方，勾选开放哪些 agent，会得到一条链接 `https://<中继域名>/i#…`。对方点开：

- 他的浏览器已经配对过自己的 Claudestra → 直接到他的「加入」页，点一下完成；
- 还没配对 → 先配对自己的机器再接续；
- 没有 Claudestra → 引导安装。

加入后两边通讯录互相出现、带在线状态；`send_to_agent("<agent>@<对方>")` 与 Peer 面板照旧。反向开放在同一条关系里点一下即可，不需要第二条链接。收回在 Peer 面板做，本机立即生效。

## peer 验签：升级后要知道的

- 别的实例调你时，必须带它自己的实例签名，签名钥匙要对得上你为它记下的指纹（邀请或兑换时记下，老 peer 是第一次签名时记下）。只拿着 token 不够——不管 token 是怎么被别人看到的。
- **两边都要升级。** 你这边的检查只保护「别人调你」；你签给对方的 token 受你保护，对方签给你的 token 要对方升级后才受同样保护。老版本对端的 `peer-http-test` 不签名，打到已升级的实例会 401（消息收发不受影响）。
- **老 peer**（你从没记下过它的指纹、它也从没签过名）默认放行到 2026-11-01，之后拒绝。`.env` 里写 `PEER_LEGACY_DEADLINE=<日期>` 可以提前或推后。`claudestra doctor` 的「peer 验签」一项列出这些 peer，「peer 验签失败」列出验签持续没通过的（10 分钟内通过过就不算，别人拿 token 乱签一次不会报），「peer 名对不上」列出入站 token 上的名字在 peer 列表里找不到的（多半是改过名：经中继的请求会被拒，移除后重新邀请）。
- **截止日之后别去加入老版本的邀请**：老版本邀请方给不出持钥证明，经 http 地址加上的这条联系人没有指纹，截止日后它发来的请求一律按 `unanchored` 拒、永远进不来。所以截止日后 `peer-join-auto` 遇到这种邀请直接拒绝并回滚，报「对方版本过旧，请先升级」；对方那边已经兑换，请对方升级后移除这条、重新生成邀请。经中继的邀请（`relay://` 地址自带指纹）不受影响。
- **被拒时按原因处理**（报错里的 reason）：
  - `stale`：两台机器时钟差超过 5 分钟，校准系统时间。
  - `key_changed` / `unsigned`：对方重装后换了实例钥匙，或者对方还是老版本。删掉这个 peer，再重新邀请（谁发邀请都行，新版本兑换时会带签名，记录里会有对方的指纹）。删掉后同名重加，之前记下的钥匙自动作废。
  - `bad`：签名和请求对不上。偶发就重发；一直这样多半是中间的反代改了路径或正文——比如把 `https://x/claudestra/api/v1/…` 剥成 `/api/v1/…` 转给 bridge，签名覆盖的是发出时的路径，就对不上。对方地址别带路径前缀，或让反代原样转发。
  - `unanchored`：截止日已过，对方从没记下你的钥匙（老 peer）。删掉这个 peer，再重新邀请。
  - `replay`：同一条请求被用了两次，不要原样重发，重新发一条。老版本在同一秒里发两条一模一样的消息也会这样（新版本每条消息带随机数，不会）：换个说法或隔一秒再发。
  - `invite_expired` / `invite_read_only`：邀请里带的 token 在邀请过期或撤销时立即失效；兑换完成前只能读。请对方重新生成邀请，或先完成加入。
  - `before_start`：对方 bridge 刚重启，而你这边的时钟比对方慢，签名时间早于它启动——校准时间后重新发。
  - `full`：对方的防重放缓存满了（只有联系人发来的、验签和发件人核对都通过的请求才进缓存，别人灌不满你的份额），稍后再发。
  - 429（`sig_rate_limited`）：一分钟里这个 peer 的验签失败超过 120 次，暂时限流；报错里带着最近一次失败的原因，先按它修好再试。429（`rate_limited`）是请求太多，稍后再发。
  - 经中继的请求被对方拒绝时，报错写的是原因（签名、时钟、重放、不是联系人），不再说成「网络不可达」。
- **重新加入不会顶掉已有的联系人。** 对方再次兑换邀请时，只有签名钥匙和你为原记录记下的一样，才合进原记录（并吊销原来那张 token）；报出的实例 id 已属于某个联系人、钥匙却对不上（包括没签名的老版本、原记录还没有指纹），兑换被拒：「这个实例 id 已绑定另一把钥匙：删掉旧联系人再重新邀请」，邀请不会被用掉；同一张邀请这样被拒 3 次就作废。确认是同一个人换了钥匙，就删掉旧那条再邀请。你加入别人的邀请时：对方（新版本）会回一份用它钥匙签的证明，钥匙和邀请里写的、和你原记录里的一致才合进原记录；对不上、或对方是老版本给不出证明而你已有它的记录，加入会回滚并提示「对方升级后重新发一张邀请，或者删掉旧联系人再加入」。
- **核对现有 peer**：`bun src/lib/doctor-peer-records.ts` 只读 `peers.json` / `peer-keys.json`，逐条列出期望指纹从哪来、上一次验签结果，以及自相矛盾的记录（指纹对不上、地址带路径前缀、同一实例 id 多条……），不打印 token 和指纹；`claudestra doctor` 的「peer 记录核对」是同一份判定。
- **轮换 token**（例如怀疑泄露）：在 Peer 面板移除这个 peer（或 `peer-http-remove <名字>`，会吊销你签出的 token），再重新邀请。

## peer 整体加密（命令行生成、私下交换的邀请）

- `claudestra peer-invite-new` 生成的邀请**默认加密**：邀请里带你的身份公钥和加密公钥。对方用新版本加入时，兑换和之后的全部协作都加密，中继只看得到谁在什么时候、传了多大的东西。邀请要走中继以外的渠道交给对方（聊天软件、当面），中继才换不了里面的公钥。设计见 [e2e-design.md](./e2e-design.md) §5.1。
- 这样建立的 peer **不会退回明文**：加密走不通就报错；对方收到这个 peer 的明文请求一律拒（`e2e_required`）。
- **对方还是老版本**：他加入时会被拒，提示「对方版本太旧，请先升级」，这张邀请当场作废。确实要连，就用 `peer-invite-new --allow-legacy` 重新生成一张明文邀请（命令会打警告：兑换和之后的协作经中继都是明文）。
- **对方重启过**时，重启前发出、还没被处理的那一条会报「对方重启过，请重发」，照做即可；报「对方已经处理过这条，不要重发」的，说明消息其实已经送到了，别再发。
- **在经中继打开的网页上**（手机壳、`https://<中继域名>` 下的页面）：生成的邀请不加密，页面会提示「中继看得到邀请内容」；加密邀请在这种页面上加不进来。想要加密，请在本机页面（电脑上直接打开的 Claudestra）或命令行生成、加入。
- 升级前建立的 peer 照旧走明文，按上面的验签规则保护。

## 这版能保证什么、不能保证什么

- 中继**不能**冒充任何实例发请求（peer 请求带实例 Ed25519 签名，接收方验签；它看得到的 peer token 单独拿去也用不了——接收方要求签名钥匙就是那个 peer 的），也不能替陌生人敲你的门（只有你列为联系人的实例能给你发帧；兑换邀请是唯一例外，限流）。设备凭据由你的 bridge 签发和校验。**注意**：中继看得到经它传的设备 cookie，拿着有管理权的 cookie 就能替你签配对码。详见 [e2e-design.md](./e2e-design.md) §1、§4.1.6。
- 中继**看得到**隧道里的明文（它就是 HTTPS 的终点，包括设备 cookie）和 peer 请求的内容，托管的 JS 也跑在你的浏览器里——信任托管中继 = 信任运营方，和任何 SaaS 一样。端到端加密的设计与分期见 [e2e-design.md](./e2e-design.md)。不放心就自建，或者走 bridge 直托管 + 自带域名（JS、更新源、TLS 全在自己手里）。
- 同一主源上配对了多台机器时，一台机器的输出若突破清洗 / CSP，能在页面存活期间借用你在这个浏览器里其它机器的凭据（偷不走，但挡不住借用）——前端按设计 §8.7 收紧了 CSP 与 markdown 清洗。
- 中继不存代码、会话、提示词、凭据；目录库里只有实例公钥、指纹、名字、最近在线时间和配对短码。
- 大文件不过中继：帧 256 KiB 上限，超过的走两端直连（后续）。

## 网页里怎么做

顶栏切换已配对的机器；「设备」面板列出每台机器上已配对的浏览器（名字、授权范围、最近使用），可撤销；Peer 面板顶部有「配对新设备」——点一下网页里直接出二维码、链接和短码，不用开终端。

## 排障

- bridge 日志里看 `🛰 中继:` 开头的行；`N 秒后重连中继` 一直刷说明连不上。
- `claudestra relay-status`：连接状态、指纹、名字、最近一次错误、联系人在线情况。`claudestra doctor` 的「手机访问」组也有中继一行。
- 常见情况：
  - `RELAY_URL` 只写主机名即可（客户端会补 `/v1/ws`）；写了别的路径就按写的连，反代没挂在那个路径下就一直重连。
  - 电脑睡眠或断网：网页里这台机器显示离线，醒来自动重连，刷新即可。
  - 网页说「这台机器需要升级」：bridge 版本低于前端要求的 `minClient` / `apiVersion`，在那台机器上 `claudestra update`。
  - 旧的 `https://<名字>.<中继域名>` 子域名地址：只对还没升到路径模式的旧 bridge 保留，截止日之后回 410 并指向新入口；重新打开 `https://<中继域名>/` 配对一次即可。经子域名进来的请求在 bridge 看来都是「经中继」，旧 web 的登录 cookie 不能再换成设备凭据（返回 404），所以从子域名打开旧 web 的浏览器也要重新配对一次。
  - 一分钟内配对码试太多次会被中继挡（429）；配对码本身 10 分钟过期、只能用一次，重新 `claudestra pair`。
