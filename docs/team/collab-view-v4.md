## 取舍

- **默认视口是「聚焦因果线」**：左区是有依赖的事项和发版里程碑，这里正是「流程往哪走」的答案。右区是各自独立推进的事项，平移或点「适配全部」才看到，大纲里一直都在。这样第一眼的重心是一条条因果链，而不是 30 张卡片。
- **边只画依赖，不画派活消息**：派活、交付、审查结论这些往来只在「团队」视图里出现，也只画最近 10 分钟的。
- **发版的 10 个前置**：左区 5 个画成汇入总线的细线；右区 5 个平时只列在里程碑节点里，选中里程碑时才临时连上，免得线缠成一团。
- **ops 任务**（F1 / N1 / T0，PM 自做）不进 DAG，只算进各事项分组框的「✓ N」。
- **品牌色**：只给最近一次推进的节点；回放时跟着推进的那一处走。

## 数据缺口（补充 data-gaps）

- **依赖和条件**：台账还没有 deps 字段，这次是 PM 手填的 `deps.json`（from / to / when / state）。要做成台账字段，并允许 PM 更新 state，同时记一条事件作为「判定依据」。
- **审查分叉的成立依据**：用的是 review 事件的 p0 / p1 和阶段，现有字段已经够。
- **时间轴回放**：用台账 stage 事件的时刻。导入的历史事件有一部分时刻是导入时刻（例如 T0 的审查），回放时这部分会挤在同一时刻。

## i28-V1：子 DAG 图 + 进度图（10-01）

owner 定调：「这两个是都要的，而不是说二选一的」。两张图用同一份数据（i28-L4 的 `GET /ledger/:project/dag` 快照，台账每重拉一次就跟着重拉，不另开事件流），可以互相跳转。代码在 `web/features/collab/dag/`，`collab-view.tsx` 只调 `useDagPanes`。

### 中区三个标签

| 标签 | 回答的问题 | 画什么 |
|---|---|---|
| **子 DAG** | 「这个 feature 的活按什么顺序做、做到哪了」 | 每个 feature 一个分组框，节点是 PR 粒度的交付；框里按依赖最长路径从左往右分列；线只画节点的 deps（前置已满足实线，否则点线），不画 task_deps、派活、审查往来。复述、审第 N 轮、修、合并、验证是节点里的六格进度条，不是节点。done 收成框左上角「✓N」（N = `counts.done`），点开才展开，连向它们的线收到 ✓N 上；missing 节点 warning 描边；没开始的（planned、卡在 spec）是小节点、不计时 |
| **进度** | 「每个 agent 此刻在干嘛」 | 每个 agent 一行，PM 永远在前；行 = 快照里的 agents + 本项目成员（没活是空闲行）+ `/agents` 的 busy（行首状态点）。每项活一枚卡片：feature 标题 · 节点 key · 步骤和轮次 · 已用时长；不在任何 feature 图里的活是灰卡。不画时间轴、不画往来线 |
| **团队** | 「谁在协作、刚刚发生了什么」 | 原样（T55） |

- **展开上限** `MAX_OPEN = 8`：默认展开 active 且有进行中节点的 feature，按最近动静降序；其余收进画布上方一条小片（done / active / idle 计数）。再展开一个时，最久没动静的那个收回小片（入场动效）。
- **回落**：bridge 太老（快照接口 404）、读失败、或本项目没有任何建了图的 feature 时，第一个标签叫「因果线」，显示原来的因果线画布；手机显示原来的分组列表。403 照入口的做法收起。
- 「待排」的卡（挂了 feature 但不在当前版里、或停在 spec）不进图，只在有人正在做时出现在进度图的灰卡里。

### 互相跳转

- **进度 → 子 DAG**：点一枚卡片，切到「子 DAG」；所在 feature 没展开就先展开（守 `MAX_OPEN`），节点是 done 就点开 ✓N；画布把节点平移到视口中间，节点闪一次。
- **子 DAG → 进度**：点节点上的负责人，切到「进度」，滚到那一行，那一行闪一次。节点上的负责人就是从进度行里认的（行里找不到才用节点自己的 handler），两张图不会说成两个人。
- 点节点主体 = 右区属性页（节点页：卡标题、状态与时长、步骤、前置、PR / 分支、取消原因），选中只存「feature + key」，每次渲染从快照重新解析。

### 版本对比

子 DAG「只能重写，不能修改」，每次重写一个新版本。每个框头有版本条：`vN`，有等 owner 批的重写时加一个呼吸的琥珀点。点开 = 右区版本页：每版的原因类型图标 + 原因首行 + 提出人 / 批准人 + 时间；选两版点「对比」，默认当前版和上一版；待批的只能当对比的 to。对比叠在图上：

| 类 | 图上 |
|---|---|
| 增 | 节点描边 + 角上 lucide `plus` |
| 删 | 用 from 版快照画虚线幽灵节点（位置照样按依赖排，不连线） |
| 带入且有改 | 角上琥珀点 |
| 取消 | 红色删除线；原因在属性区 |
| `rewrittenDone`（已完成节点被改写） | error 色描边 |

对比时这个框的 done 节点全部展开（标记可能就在它们身上）。差异页按这几类列清单，取消的带原因。
