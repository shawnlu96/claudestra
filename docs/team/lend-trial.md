# 借算力试用手册（出借方 B / 借入方 A）

给第一次真人试用用的：B 把空闲的 Codex 位借给 A，A 的调度器把审查单推给 B，B 自动领单、在自己机器上起一次性 worker 审完，结论记进 A 的台账。
协议和失败处理见 [`docs/design/remote-capacity.md`](../design/remote-capacity.md)；本手册的每一步都在 lab 里跑过，实测记录见 [lend-trial-evidence.md](./lend-trial-evidence.md)。

凡是要本人动手的，都写的是网页上的哪个按钮。还没有按钮、只能跑命令的，统一列在文末「缺口」一节，正文不让本人跑命令。

## 0. 两边先确认（一次性）

| 要确认的事 | 在哪看 |
|---|---|
| 两边都已升级到含 i28-W7 的版本（升级会把第四个服务「调度服务」一起装好） | 设置 → 通用 →「版本与更新」：看「当前」那一行；旧了点「**升级 Claudestra**」 |
| 两边已互加 peer（一键邀请） | 设置 → **Peer 协作** → peer 列表里有对方，状态在线 |
| B：Codex 适配器已装、已登录 | Codex 有新版时网页顶部会出「Codex 可更新」提示条，点它更新；登录见「缺口」 |
| B：机器上没有代理变量（`http_proxy` 之类），配了 `CONTROL_CHANNEL_ID` | 见「常见失败」最后两条 |

## 1. 出借方 B 要做的

1. 设置 → **Peer 协作** → 页面下方「**出借**」面板 → 点「**授权**」。
2. 表单：
   - 「对象」选 A；
   - 「仓库」填 `owner/repo`（回车加一个，可加多个）；
   - 「角色」固定是审查，写代码锁着；
   - 「codex 名额」填同时最多跑几个；
   - 「每日单数」；
   - 「到期」从 1d 到 7d 里选一档。
3. 读一遍表单上那句黄字（「这会让发起方的任务在你的用户下随时起 shell」），点「**提交授权**」。
4. 收回：同一面板里，这条授权右边的「**收回**」。在跑的 worker 当场停，单退回 A，A 自动改放本机。
5. 到期或被暂停的条目，右边按钮会变成「**重新授权**」。

授权以后不用再点任何东西：来单直接领，开跑和交付各给你发一条通知。

## 2. 借入方 A 要做的

1. 设置 → **Peer 协作** → 「**借入**」面板 → 点 peer 列表下方那个带 B 名字的 **＋** 按钮。
2. 勾选允许外借的项目，用「上限」两边的 −/＋ 设同时最多放几单，点 ✓（「借入」）。
3. 想让审查优先给 B（reviewFirst）：网页上目前只读，由 PM 改 `scheduler.json`（见「缺口」）。不改也行：按「在跑最少」平均分，B 有空位就会分到。

## 3. 怎么确认生效

| 看什么 | 在哪 |
|---|---|
| B 的授权在 | B：出借面板里那一条显示剩余时间，没有暂停 / 到期标记 |
| A 收到了 B 的 hello | A：借入面板里 B 的卡片显示「**推送派单**」（只显示「只轮询」= 对方是旧版，见第 4 节）、hello 是几秒前、「今日余 N 单」 |
| 单子推过去了 / 在跑 | A：借入面板下的「**远端在跑**」；B：出借面板里的「**借出中的单**」 |
| 结论入账 | A 的台账（卡片时间线）依次出现：<br>· `出借：审查挂给 B（codex）`<br>· `出借：B 领了审查（agent-lend-…）`<br>· review 事件 `远端审查（B，单号 lend:…）：pass/changes`（家族、会话标为对方自称）<br>B：出借面板「近期已结束」里这单变成已交付，收据一行 |

## 4. 常见失败和处理

- **旧条目被暂停**：升级前用逐单确认写的条目，升级后显示暂停标记，不会领单（为安全起见故意如此）。处理：B 点「重新授权」。
- **到期时间格式**：网页只给 1d–7d 的档位，不会填错。命令行的 `--until` 收 ISO 时间或 `3d` / `12h` 这样的时长，最长 7 天（设计稿 §1.1 写的 90 天是旧说法，以代码的 7 天为准）。
- **上限**：B 的名额满了，A 推来的新单当场被拒收（`no_slot`），A 立刻撤单：
  - 自动卡改放本机；
  - 手挂的单通知 PM。
  - A 借入面板里 B 的空位显示 0；PM 在 A 上查 `ledger lend-orders <卡>` 能看到原因（例如「mate：对方没有空闲的 codex 槽」）。
- **收回**：在跑的 worker 当场停，A 那边这单变成 released，自动改放本机，不会再推给 B，直到 B 重新授权。
- **B 关机或调度服务没在跑**：
  - 推过去的单被拒收（`lender_idle`），A 立刻撤单；
  - worker 跑到一半掉线：B 到租约截止（10 分钟）自停，A 把这单记成「结果不明」交 PM，不自动重派。
- **B 授权写了模型以后，在网页上点「重新授权」**：模型和推理档会被清掉，改用 B 本机 Codex 的默认配置（见证据「问题 2」）。设了模型的话先别在网页上重授，等修复。
- **开跑通知发不出去就不起 worker**：B 的 `.env` 里 `CONTROL_CHANNEL_ID` 是空的时候，B 会一直卡在「开跑通知没交出去，暂不起 worker」。网页安装会自动写好这一项，手装的机器要补（见「缺口」）。
- **代理变量**：B 的环境里有 `http_proxy` 之类的变量时一单都不领。`doctor` 里会报 warn。

## 缺口：还要本人跑命令的步骤

| 步骤 | 现在只能这样 | 谁来补按钮 |
|---|---|---|
| 授权里指定 Codex 模型 / 推理档 | `manager lend grant <A> --repos … --until … --codex-model <模型> --codex-effort <档位>`（网页表单没有这两项，网页重授还会清掉，见证据「问题 2」） | 新节点：网页授权表单加两项，重授保留原值 |
| A 的 `remote.reviewFirst` / `remote.mode` | 改 `scheduler.json`（借入面板只读）。由 PM 改，不是本人 | 新节点：借入面板加写入口 |
| Codex 登录 | B 在终端里跑 `codex login`（网页只有适配器更新按钮） | 待定 |
| `CONTROL_CHANNEL_ID` 为空的手装机器 | 编辑 `.env` 补上，再重启服务 | 待定 |
| 查第四服务、代理变量 | `manager doctor`（只读） | 网页体检页 |
